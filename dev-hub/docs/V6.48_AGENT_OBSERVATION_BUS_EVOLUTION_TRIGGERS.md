# V6.48 — Agent Observation Bus & Continuous Evolution Triggers

Status: IMPLEMENTATION / NOT ACQUIRED

## Goal

V6.47 established evidence-backed fleet measurement. V6.48 makes evidence collection continuous at common execution and verification boundaries so agents can accumulate trustworthy evolution evidence without bespoke telemetry per agent.

## Core rules

- Agent self-reporting is allowed for observability but can never become VERIFIED evidence.
- VERIFIED requires an independent trusted source and evidence references.
- Unknown verifiers are downgraded to OBSERVED.
- Every event carries exact lineage: source, subject role, project, event type, outcome and evidence.
- Events are idempotent by event_id and chained by SHA-256 digest.
- The bus is append-only.
- Reassessment triggers never directly mutate an agent and never directly materialize a candidate.
- Agent Foundry remains candidate owner.
- Logician remains advisory.
- Technology Watch revalidation remains required.
- Guardian/Sentinel preserved.
- Architecture Council final.
- Automatic external spend remains 0 EUR.

## Common instrumented boundaries

### Run Controller
Publishes TASK_EXECUTION_OBSERVED events for actual execution outcomes, attempts, failure class, capabilities and Guardian pre/post state.

### Project Control
After independent verification through Verification Broker, publishes TASK_RESULT_VERIFIED with VERIFIED status, exact task owner role and evidence references.

## Continuous triggers

Verified events such as VERIFIED_FAILURE, ROLLBACK, SECURITY_INCIDENT, PERMISSION_DRIFT and Technology Watch material deltas create a REASSESS request in the Agent Evolution queue.

A trigger means: measure and challenge the agent again.
It does not mean: rewrite or promote the agent.

## Fleet Observatory enrichment

The V6.47 observatory now reads the common bus for:
- capability coverage;
- verified handoff quality.

Unknown dimensions remain UNKNOWN.
