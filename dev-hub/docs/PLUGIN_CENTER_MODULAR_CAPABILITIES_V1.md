# ChaCha DEV Plugin Center — Modular Capabilities V1

## Objective
ChaCha DEV improvement discoveries are modular by default. A useful mechanism discovered by Technology Watch, competitive intelligence, Dark Intelligence, Technology Truth or runtime evidence is built as a recipe-first `PLATFORM_PLUGIN` whenever it does not require a justified core mutation.

## Boundary
The Plugin Center is not an alternate authority plane. It cannot directly mutate production, bypass Guardian/Sentinel, switch `current`, delete persistent data, or uninstall core authority components.

`CORE_LOCKED` includes the central orchestrator, Guardian, Sentinel, UMG, CCR, Architecture Council, emergency STOP, governed platform promotion and Intendant. These are visible governance foundations, not removable plugins.

## Lifecycle
`DISCOVERED → BUILDING_SHADOW → QUALIFIED_RECIPE_ONLY → INSTALL_REQUESTED → ACTIVE → DISABLE_REQUESTED → DISABLED → UNINSTALL_REQUESTED → UNINSTALLED_RECIPE_ONLY → REINSTALL_REQUESTED`.

Install means **rebuild from sealed recipe, verify, then use the existing governed activation path**. A qualified plugin therefore does not need to occupy permanent runtime storage while waiting for installation.

Disable precedes uninstall. ChaCha verifies platform health and the dependency graph before runtime removal. Uninstall removes only the runtime material by default: Git history, sealed recipe, manifest, provenance, evidence and persistent data survive. Persistent-data deletion is a separate destructive operation requiring its own Intendant/Guardian/human gate.

## Manifest
Every plugin identifies exact source revision/tree, functional value, capabilities, permissions, dependencies, conflicts, persistent data, recipe digest, qualification evidence, rollback contract, license/provenance and SBOM when external source code is reused.

## Cockpit
The owner cockpit exposes `🧩 Plugins` with active, disabled and recipe-only capabilities and contextual actions: Install/rebuild, Disable, Uninstall, Reinstall. Clicking an action creates a governed BUILD intent; the UI never performs a direct production mutation.

Consultant identities never receive the Plugin Center API or cockpit surface.

## Factory rule
External novelty is never sufficient. An improvement must first pass the global-value gate. The default delivery form is `PLUGIN_PACKAGE`; a `CORE_TRAIN` is exceptional and requires Architecture Council justification that modular delivery cannot satisfy the requirement safely.

## Storage model
Plugins follow the same recipe-first principle as update trains. Runtime artifacts are disposable caches. The sealed recipe and exact Git lineage are the reconstruction authority.
