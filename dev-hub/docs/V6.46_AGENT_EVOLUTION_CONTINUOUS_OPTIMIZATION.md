# V6.46 — Agent Evolution & Continuous Optimization Framework

Status: IMPLEMENTATION / NOT ACQUIRED

## Scope correction: Technology Radar

`technology-radar-agent` is not a ChaCha DEV central-brain role.

It is project-scoped to **WfGg Radar** and must never be selected by platform-global routing. Generic technology discovery, validation, version selection and architecture watch belong to `technology-watch-agent`.

This removes the naming/scope collision between the WfGg Radar application and ChaCha DEV Technology Watch.

## Principle

**An agent is never considered permanently finished.**

Every agent has:
- an active version;
- a scorecard;
- technology freshness;
- agent debt;
- evidence history;
- observed failures and rollbacks;
- handoff quality;
- learning quality;
- a candidate-evolution lifecycle.

Agents may observe themselves, report debt, request reassessment and propose evolution. They may **not** mutate their active implementation, promote themselves, expand their own permissions or disable assurance.

## Continuous evolution loop

`OBSERVE -> ASSESS -> PROPOSE -> SHADOW -> PILOT -> ADOPT`

Technology Watch continuously watches technologies, coding patterns, architectures, runtimes and tools relevant to every agent.

Logician challenges the agent and the proposed candidate with counterexamples and falsification paths.

Agent Foundry materializes the candidate as an isolated version.

The incumbent remains the control group.

Guardian checks permission/contract drift. Sentinel checks code and regression. Architecture Council remains final architecture authority.

## Regular cadence

- event-driven immediately after material incidents or technology changes;
- lightweight health every 24 hours;
- deep agent audit every 7 days;
- ecosystem benchmark every 30 days.

Material events override the cadence and trigger immediate reassessment.

## Evolution surfaces

An agent can evolve in:
1. functions/capabilities;
2. internal architecture;
3. implementation code;
4. toolchain/providers;
5. prompts/policies;
6. tests/evidence;
7. handoff contracts;
8. memory/learning;
9. observability;
10. resource/cost profile.

## Scorecard

No single opaque score replaces the dimensions.

Each agent is measured independently on:
- accuracy;
- coverage;
- calibration;
- evidence quality;
- robustness;
- efficiency;
- handoff quality;
- learning quality;
- drift resistance;
- authority discipline.

Agent Debt is a separate remediation indicator, not an authority score.

## Promotion rule

A newer agent version has no priority merely because it is newer.

Promotion requires measurable gain, no material regression, permission non-escalation, exact-revision evidence and rollback.

Automatic external spend remains 0 EUR.
