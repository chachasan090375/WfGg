# Autonomous Improvement Factory V1

ChaCha DEV converts verified competitive, Technology Watch and Technology Truth findings into update trains only when a measurable global platform benefit is demonstrated.

## Decision hierarchy
1. Reuse an existing internal capability.
2. Reuse compatible open-source code when provenance and license obligations are verified.
3. Otherwise reconstruct the mechanism as an owned ChaCha DEV component.
4. Use a plugin/connector only when a reasonable owned path is unavailable.

Novelty is not value. A train is rejected if it does not materially improve autonomy, reliability, security, performance, cost efficiency, maintainability, UX or capability coverage.

## Separation of authority
The out-of-band observer never builds or promotes. It issues evidence-backed improvement requests. The central orchestrator and existing Creation Runtime/Foundries build in shadow. Guardian, Sentinel, UMG, CCR and exact-SHA qualification remain mandatory. The Cockpit Update Center is a human promotion surface, never a direct `current` switch.

## Update Center
Each train exposes functional change, expected platform value, source/provenance/license strategy, dependencies/conflicts, qualification and rollback readiness. Per-train and batch buttons initiate the governed promotion pipeline. Batch execution is dependency-aware and never parallelizes conflicts.
